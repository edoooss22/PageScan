# PageScan

Мини-сканер одного признака: **приватные страницы внутри образов процесса**.
Находит код и данные только для чтения, в которые писали после загрузки, — в том числе
если байты уже вернули на место. Результат — один `.html` в том же виде, что у McScanner.

Отдельный инструмент: исходники McScanner не использует и не меняет.

## На чём держится проверка

Код загруженной библиотеки физически общий: одну и ту же страницу видят все процессы,
где загружен файл. Первая же запись отделяет приватную копию страницы, и обратно к общей
она не привязывается. Вернуть исходные байты можно, отменить отделение копии — нет.

Отсюда три вывода, которые не зависят от имён модулей и версий игры:

| Состояние страницы кода | Что это значит |
|---|---|
| приватная, байты совпадают с файлом | писали и вернули как было — снятый перехват |
| приватная, короткое отличие в начале функции | перехват стоит прямо сейчас |
| приватная, отличается больше половины страницы | поверх кода модуля записан другой код |

Смена прав доступа без записи такого следа не оставляет — это проверено тестом.

## Как устроена

1. Берутся все образы процесса по карте памяти (а не по спискам загрузчика, которые
   правятся изнутри процесса).
2. У каждого образа проверяются заголовок и все секции без права записи: код и данные
   только для чтения. Раскладка секций берётся из файла на диске.
3. Состояние каждой страницы запрашивается у ядра одним запросом на секцию. Решает
   **разряд происхождения** страницы («прообраз общий»), а не разряд «общая» — см. ниже.
4. Страница, которой нет в памяти, не читается, если ядро помнит её общий прообраз.
   Остальные читаются по одному байту: чтение возвращает страницу в память, и видно,
   какой она вернулась.
5. Каждая приватная страница побайтно сверяется с файлом. Адреса, которые правит перенос
   базы, пересчитываются. Места, куда штатно пишет загрузчик, вычитаются **по байтам**,
   а не страницами целиком: таблица адресов импорта, отложенный импорт, указатели
   проверки вызовов (CFG), поле базы в заголовке, перенос базы внутри процесса,
   секция `.mrdata`, заголовок сборок .NET.
6. Для каждой правки в коде определяется, пришлась ли она на начало функции (таблица
   раскрутки стека и экспорт файла), и разбирается записанный переход: он прослеживается
   через промежуточные заглушки до образа, который получает управление.

Из процесса читаются только заголовки образов, сами приватные страницы и по байту из
вытесненных страниц без общего прообраза. На чистой игре это около 300 страниц из
92 тысяч; проверка занимает меньше секунды.

### Почему разряд происхождения, а не «общая»

Страница, в которую писали, может снова числиться общей. Замер на чистой игре: сразу
после запуска 291 приватная страница, через несколько минут по разряду «общая» их остаётся
169 — у 122 страниц таблиц импорта выставлен разряд «общая» и счётчик ссылок 5–7, а ещё
через несколько минут они опять приватные. Содержимое таких страниц одинаково во всех
процессах, и картина совпадает с тем, как Windows объединяет одинаковые страницы памяти
(page combining); сам механизм здесь не доказывался, измерены только разряды. Разряд
происхождения при этом не меняется ни разу: прообраз такой страницы общим не был. В отчёте
эти страницы помечены словом «объединена».

Если система разряд происхождения не отдаёт (ни у одной действительной страницы он не
выставлен), сканер переходит на разряд «общая» и пишет об этом в сведениях о проверке.

## Запуск

```
PageScan.exe                 процесс Minecraft ищется сам
PageScan.exe --pid 1234      проверить процесс с этим PID (любой, не только Java)
PageScan.exe --list          показать процессы java/javaw
PageScan.exe --out <dir>     каталог для отчёта (по умолчанию reports рядом с exe)
PageScan.exe --open          открыть отчёт в браузере
PageScan.exe --verify-all    перечитать и страницы, которые ядро считает нетронутыми
```

При запуске двойным щелчком отчёт открывается в браузере сам, а окно ждёт клавишу.
Запускать от имени администратора: без прав отладки чужой процесс может не открыться.

Коды возврата: 10 — есть КРИТИЧНО, 9 — ВЫСОКАЯ, 8 — СРЕДНЯЯ, 0 — чисто, 2 — процесс не
найден, 3 — ошибка.

## Находки

| Категория | Находка | Значимость |
|---|---|---|
| КОД | в код писали и вернули байты как было | КРИТИЧНО для системных библиотек, библиотек Java и LWJGL; иначе ВЫСОКАЯ |
| КОД | точечная правка кода | КРИТИЧНО, если в начале функции или переход ведёт в исполняемую память вне образов; иначе ВЫСОКАЯ |
| КОД | код замещён другим содержимым | ВЫСОКАЯ |
| КОД | код изменён во многих местах | СРЕДНЯЯ; ВЫСОКАЯ при переходе вне образов |
| КОД | страницы кода приватны, а сверить их не с чем | ВЫСОКАЯ |
| ЗАГОЛОВОК | заголовок образа стёрт или испорчен | ВЫСОКАЯ |
| ЗАГОЛОВОК | заголовок изменён / писали и вернули | СРЕДНЯЯ |
| ДАННЫЕ | в данные только для чтения писали | НИЗКАЯ; ВЫСОКАЯ, если записанный адрес ведёт в исполняемую память вне образов |
| СПРАВКА | модуль правит свой код сплошной полосой | ИНФО |

«Полоса» — шесть и более подряд идущих изменённых страниц, на каждой из которых отличается
меньше половины байт: так драйвер видеокарты правит адреса в собственном коде. Если на
таких страницах отличается больше половины, это уже замещение кода, а не полоса.

Вкладка «Полные данные» отчёта: метод, сводка по всем образам, постраничный список
приватных страниц с причинами, итог перепроверки вытесненных страниц.

## Замеры

Чистая игра (Fabric 0.19.3, Minecraft 1.21.10, 145 образов, 92 398 страниц): находок
0/0/0/0, одна справочная строка — полоса из 94 страниц в `nvoglv64.dll`. Остальные
197 приватных страниц объяснены: таблицы импорта, указатели CFG, `.mrdata`.

Ключ `--verify-all` на той же игре: 78 529 вытесненных страниц с общим прообразом
перечитаны, все вернулись общими — правило «не читать то, что ядро считает нетронутым»
ничего не пропускает.

Системные процессы (`explorer`, `sihost`, `RuntimeBroker`): находок нет.

Процессы с настоящими перехватами показывают, что отчёт называет владельца: в Firefox
18 перехватов в `ntdll.dll` ведут в `mozglue.dll` и `firefox.exe`, в Discord и приложениях
на Electron — перехваты песочницы и оверлея.

## Положительный тест

```
tests\positive\run-test.cmd
```

Тест собирает цель `PageScanTarget.exe`, которая делает сама с собой всё, что должен
ловить сканер, и сверяет отчёт с ожиданием:

| Что делает цель | Ожидаемая находка |
|---|---|
| пишет байт в `kernel32!Beep` и возвращает его | КРИТИЧНО, писали и вернули |
| то же в `version.dll`, затем вытесняет страницы из памяти | ВЫСОКАЯ, страница была вытеснена |
| ставит переход в начало `dbghelp!SymCleanup` на память вне образов | КРИТИЧНО, начало функции, вне образов |
| затирает 8 страниц кода `msxml6.dll` | ВЫСОКАЯ, код замещён |
| меняет 6 участков на одной странице | СРЕДНЯЯ, изменён во многих местах |
| пишет адрес заглушки в `.rdata` | ВЫСОКАЯ, адрес ведёт вне образов |
| стирает заголовок `msftedit.dll` | ВЫСОКАЯ, заголовок стёрт |
| пишет в заголовок `riched20.dll` и возвращает | СРЕДНЯЯ, писали и вернули |
| меняет права страницы туда и обратно без записи | находки быть не должно |

Цель печатает сырые разряды записей страниц до и после каждого действия — по ним
выведены правила разбора. Лишняя находка значимостью от средней считается провалом теста.

## Чего проверка не видит

- код вне образов (приватная исполняемая память) — только как цель перехода;
- запись в секции, объявленные в файле доступными на запись, включая код с правом записи;
- запись в страницу, содержащую адреса переноса базы, у образа, который загрузчик
  переносил внутри процесса, если байты после этого вернули;
- подмену адресов внутри таблицы импорта: такие байты считаются записью загрузчика.

## Сборка

```
build.cmd
```

Нужен .NET SDK 8. Получаются две сборки одного и того же кода:

| Файл | Размер | Что нужно на проверяемой машине |
|---|---|---|
| `dist\PageScan.exe` | 37 МБ | ничего: среда .NET вшита в файл |
| `dist\PageScan-lite.exe` | 0,4 МБ | установленный .NET 8 Runtime (x64) |

Если .NET 8 на машине нет, `PageScan-lite.exe` не запускается: печатает в консоль
«You must install or update .NET to run this application» со ссылкой на загрузку и
выходит. При запуске двойным щелчком окно при этом сразу закрывается, поэтому облегчённую
сборку на незнакомой машине запускайте из консоли.

Положительный тест можно прогнать на любой из сборок:

```
tests\positive\run-test.cmd -Scanner dist\PageScan-lite.exe
```
